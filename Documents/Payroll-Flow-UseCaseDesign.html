User (บุคลากร)

04

Flow ข้อ 1 — การเชื่อมโยงข้อมูล Authen จาก API

ลำดับการทำงานจริงตามโปรเจ็ค api_authen_of_med — login ด้วย application-key + JWT แล้วดึงข้อมูลบุคลากร (PMIS) มาแสดง

Phase A · เข้าสู่ระบบ (Login)
1ผู้ใช้ → FEกรอกข้อมูลกรอก username / password ที่หน้า Frontend
2FE → BEส่งต่อส่งข้อมูล login ไปยัง Payroll Backend
3BE → APIrequestPOST /api/employee/login · แนบ header application-key (secret เข้ารหัส AES) + body {username, md5(md5(password))}
4APIประมวลผลverifySecretKey → ตรวจสอบ credential กับฐานข้อมูลบุคลากร
5API → BE200 สำเร็จคืน JWT access token + ข้อมูล user
5API → BE401 ล้มเหลวคืน Unauthorized → FE แจ้ง "username / password ไม่ถูกต้อง"
6BE → APIดึง PMISGET /employee/username/:username + /profileImg (ป้องกันด้วย application-key)
7API → BEmaster dataคืน ชื่อ-นามสกุล, รหัสบุคลากร, รูปภาพ, ธนาคาร / เลขบัญชี
8BE → FEเข้าระบบส่ง token + profile → แสดงหน้า Profile ของผู้ใช้
Phase B · ทุก request ถัดไป
9FE → APIverifyแนบ Bearer token → GET /authenticate → verify + refresh token (อายุ 1 ชม.)
สรุปกลไก: ระบบ Payroll ไม่เก็บรหัสผ่านเอง — ยืนยันตัวตนผ่าน API กลางของคณะฯ 2 ชั้น: application-key (ยืนยันว่าเป็น client ที่ได้รับอนุญาต) และ JWT Bearer token (ยืนยัน session ผู้ใช้) ส่วนข้อมูลพื้นฐานบุคลากรเป็น master data ที่ดึงสด ไม่แก้ไขในระบบ Payroll
